This is a handoff design, not an implementation authorization. It separates “code exists but its contract is incomplete” from “the capability is intentionally unsupported.” A slice is READY/VERIFIED only after implementation, failure cleanup, concurrency reasoning, focused tests, and the required independent review. Physical-hardware work is explicitly deferred because this environment cannot provide the required evidence.

Constructor errors carry the backing and armed reservation for ordered cleanup; map replacement mismatches return `CapacityInvariant` while preserving the live map/charge, and empty-map reclamation fails closed without an invariant panic. Two independent U23 reviews pass these safe ownership paths. ## 0. Requirement, threat model, and review boundary

The target is an honest, bounded kernel contract for every README component: a supported call either performs the documented operation or returns its documented error without side effects. The attacker may control syscall arguments, user memory, file descriptors, namespace/cgroup membership, packet/device input, and timing. Firmware and devices are untrusted inputs; host tooling is not a kernel oracle. The trust boundary is Ring 3 to kernel entry, then kernel services to VFS, network, block, and IOMMU objects.

Cross-cutting invariants are: no user-controlled length or index causes an unchecked allocation or access; every resource has one admission owner and one release path; publication is atomic with respect to the relevant lock/generation; cleanup is safe after any partial failure; blocking/I/O never occurs while holding an IRQ or registry lock; unsupported features fail closed; and every claimed capability has a behavior, failure, resource, and source/image identity oracle.

The blast radius spans `kernel/kernel_core/syscall.rs` and `process.rs`, `kernel/mm`, `kernel/ipc`, `kernel/vfs`, `kernel/net`, `kernel/sched`, `kernel/iommu`, `kernel/security`, `kernel/livepatch`, `bootloader`, and the userspace/scripts gates. A change in a shared owner, syscall ABI, lock order, or page-table root requires the high-risk review and gate set named in Sections 3–9.

### Candidate strategy and decision

Two strategies were considered: (A) implement each Linux surface in one broad compatibility push, or (B) land dependency-bounded slices with an explicit unsupported boundary and a measurable oracle. Strategy B is chosen because it keeps rollback ownership local, allows the current QEMU gates to remain truthful, and defers physical-only claims. The only exception is a future full redesign when a real write-back, slab, or passthrough consumer changes a stated premise; do not silently widen a current slice.

## 2. UEFI, boot, and early W+X (P2/P3; deferred platform evidence)

### Current gap

`bootloader/src/main.rs` already performs PIE relocation, KASLR, BootInfo publication, and memory-map handoff. The early identity/high-half mappings still create a temporary W+X window (R188 U55-6), and only x86_64/OVMF-like configurations are exercised locally.

### Design

1. After parsing the EFI map, build an immutable `BootMapReceipt` containing physical range, final permission, descriptor source, and temporary status. Use half-open intervals and checked arithmetic; overlap, overflow, misalignment, or unknown descriptors stop boot.
2. Build final permissions before the CR3 handoff: RX `.text`, R `.rodata`, RW+NX data/heap, and non-executable MMIO. Scan aliases so no physical page is W+X. Remove the low identity map after the entry trampoline is no longer needed.
3. `kernel/src/main.rs` consumes only validated BootInfo ranges and never recomputes a physical base from constants. Failure prints the descriptor index/reason and halts.
4. Keep firmware/CPU capability profiles separate. Real firmware, physical topology, and early-W+X qualification are deferred until a named hardware environment is available.

### Oracles

Inject oversized/overlapping/overflowing memory maps and framebuffer ranges; expect fail-closed startup. Inspect page tables before and after the handoff and require no writable executable alias. `make boot-check` must reach Ring 3 and retain image identity; QEMU success is not a physical-platform claim.

## 3. Memory management and virtual memory (P0/P1)

### 3.1 Admission closure (P0-A/R186-4)

`kernel/kernel_core/fork.rs` builds the child snapshot/page tables while `kernel/mm/heap_admission.rs` owns reserved/committed counters and `kernel/mm/admitted.rs` owns admitted containers. The current implementation reserves the exact snapshot charge before allocation, transfers one reservation into the adopted `AdmittedMap`, and performs no infallible shrink. The induced COW/PT/child-publication cleanup oracle, map mismatch path and constructor-owner cleanup oracle pass locally; two independent U23 reviews pass the safe ownership paths.

Implementation must preserve one capacity-sized charge and one owner transfer. `try_reserve` precedes snapshot allocation; the reservation moves once into the adopted `AdmittedMap`; no release/reacquire cycle is allowed. Constructor errors return the backing and armed reservation together, and callers drop the backing before the reservation. Parent PTE COW is the commit point. Every earlier failure (PCB, fd/cgroup charge, child root, KPTI root, COW plan) rolls back exactly once; after commit there is no recoverable error. Ordinary `CorruptState` errors propagate; the `HeapReservation`/`HeapCharge` Drop fail-stop remains an intentional boundary only after prior counter corruption and is unreachable through the linear safe API. Removing a logical map entry retains its capacity charge until physical retirement.

Acceptance records reserved/committed deltas for normal, OOM, page-table, child-publication, fork/exec/unmap/reap, and pressure paths. The final remote copy `/tmp/zero-os-codex-final-20260913` on `40c-devbox-ts` verifies MM 26/26, kernel-core 68/68, the validation-only hosted allowlist (438 executions plus CpuLocal doctest and three compile checks), `make build`, and `make lint`. The shared-fault cleanup hardening is included and its final hashes are `fork.rs` `d6ffc1e6076f8b4fae699aa3af66f35a19ebb19121fd29916e3bc2511a8b033c` and `capabilities.rs` `dd097a1d994b475219919a415e4513dc33c52686a89e9811f01501d9f4fa7061`. Runtime, boot, and four-core SMP are qualified with zero failures (35/39/0, 28/46/0, and 37/37/0 respectively); musl remains incomplete because required guest markers are absent.

### 3.2 mmap flags, MAP_SHARED/MAP_FIXED, file mappings (ST-K2)

`sys_mmap` at `kernel/kernel_core/syscall.rs:14118` implements anonymous mappings in a three-phase VMA/PT transaction. The current tree validates the entire flags word after the LSM hook (`validate_mmap_flags`, `syscall.rs:11916`, called at `:14170`): exactly `MAP_PRIVATE|MAP_ANONYMOUS` and `MAP_SHARED|MAP_ANONYMOUS` reach the anonymous path, while MAP_FIXED, incomplete/shared-validate forms and unknown bits return `EOPNOTSUPP` before VMA/cgroup/PT mutation. File-backed `mmap` (`fd >= 0`) returns `EOPNOTSUPP` at `:14180-14185`, and shared `PROT_NONE` returns `EOPNOTSUPP` at `:14199-14202`.

**Phase 1:** implemented after the LSM hook and before VMA mutation. The validator accepts `MAP_PRIVATE|MAP_ANONYMOUS` and the shared-anonymous Phase 2 shape; unknown bits, `MAP_SHARED` without `MAP_ANONYMOUS`, `MAP_SHARED_VALIDATE`, and `MAP_FIXED` return `EOPNOTSUPP`. Existing alignment, stack-window, brk-reservation, overlap, map-count, and cgroup checks remain. `run_mmap_flags_self_test()` is wired into the integration memory-mapping gate. Since 2026-10-25 (R192-RES-3) `MAP_FIXED_NOREPLACE` is accepted with either anonymous shape: it maps exactly at `addr` or fails (`EEXIST` taken, `EPERM` below `MMAP_MIN_ADDR`, `ENOMEM` past the top, `EINVAL` unaligned) and never replaces; a plain non-zero `addr` is a hint that falls back to automatic placement when its range is unusable; `MAP_FIXED` stays `EOPNOTSUPP`. Report pages and CPU worker results in `userspace/stress_runner.c` now use bounded pipes with short-I/O, EINTR, EOF, child-failure, and oversized-record handling. The CPU profile uses one pipe per worker; SMP and combined profiles still intentionally use their shared counters and remain a Phase-2 boundary. Missing records are incomplete, never zero work.

**Phase 2 progress:** shared-anonymous entries use an admitted `SharedAnonRegion` side map (`kernel/kernel_core/fork.rs:2117`, held per-MM in `Process`'s `shared_regions` at `process.rs:1331`) whose slot backing and `HeapCharge` are fully reserved at `try_new` (`:2126`) before any allocation, so the charge survives until the region Arc is finally dropped (`Drop` at `:2182`). `sys_mmap` publishes metadata without allocating data pages (`syscall.rs:14357`); the first user or usercopy fault charges its cgroup, zeroes one page, maps it, and records the owner in `handle_shared_page_fault` (`fork.rs:1868`), which holds only try-locks and reserves the bounded DATA+PT receipt before `PT_LOCK` (`:1961-1974`); `map_page` failure detaches only proven-empty intermediate tables and retains reachable PT frames in the accounting (`:2050`). Fork copies side-map Arcs and shared leaves with writable flags while adding exactly one mapping reference (shared ranges collected at `:877-887`, PT bound reserved by `reserve_shared_fault_pt`, `process.rs:1622`); parent PTEs remain unchanged. Shared `mprotect` returns `EOPNOTSUPP` before any boundary split (`syscall.rs:15359-15367`), and shared `PROT_NONE` is rejected in `sys_mmap`. The 2026-09-20 lifecycle follow-up records new guest usercopy, teardown and migration evidence; full failure/race coverage and the shared-mmap musl marker remain qualification limits.

**mremap (implemented 2026-09-14 for private anonymous VMAs):** `sys_mremap` (`kernel/kernel_core/syscall.rs:22459`) is no longer the M0-6 `ENOSYS` stub. It resizes a private-anonymous or private-`PROT_NONE` VMA in place, or relocates it under `MREMAP_MAYMOVE`, using the same three-phase VMA/page-table/accounting transaction as `sys_mmap`/`sys_munmap`: validate the complete old VMA and the whole flags word, reserve the destination (blocking concurrent fork/mmap/munmap through the existing transient flags), install every destination PTE, then remove the source and commit the VMA plus the cgroup delta atomically with migration. `old_size` must match the live VMA exactly; `MREMAP_FIXED`, `MREMAP_DONTUNMAP`, unknown bits and shared-anonymous VMAs return `EOPNOTSUPP` before any mutation. Shared-anonymous resize is refused because `SharedAnonRegion` is snapshotted into every fork child, so resizing it would let a child re-fault a range the parent no longer owns — a per-VMA identity model is the prerequisite. See [st-k2-mremap-anonymous-design.md](https://github.com/Zero-kernel/Nilix-docs-private/blob/main/design/st-k2-mremap-anonymous-design.md). The page-table/refcount behavioral legs now run for real: the Ring-3 fixture (`userspace/src/syscall_test.rs`) drives grow-in-place, shrink, `MREMAP_MAYMOVE` relocation, the blocked-grow `ENOMEM` refusal and the fail-closed errno matrix through actual syscalls, under `make test-ring3-mm`. That gate is deliberately separate from `make test` because the shared-anonymous model IS demand paging, so exercising it necessarily emits `[PF ENTRY]` on handled faults — the same collision `open_fault_probe.py` documents for the musl workload. On its first run the Ring-3 oracle found two real defects (a release-build underflow on the shrink path and an in-place grow that stranded `next_mmap_addr`); both are fixed, with a hosted regression guard for the first.

**File mappings (not implemented; fail closed):** file-backed `mmap` still returns `EOPNOTSUPP`. The intended design, for whoever implements the slice, is to resolve a pinned `FileHandle`/`Inode` with page-cache key `(fs_id, ino, index)`; `kernel/mm/page_cache.rs` already provides `read_page`/`find_or_create_page`/`writeback_dirty_pages` keyed by `InodeId`/`PageIndex`, so the slice is more tractable than this paragraph previously implied. Nothing here is evidence of current implementation.

Execution environments remain distinct: the mmap/COW/capability integration self-tests execute in the guest, not merely by compiling the hosted allowlist. Hosted kernel-core now executes shared-region metadata and shared-fault PT provenance tests, not actual sys_mmap/page faults. That re-run is the evidence that the process-lifecycle changes did not regress the memory subsystem; it is not new memory coverage. A later run the same day added the §4 `waitid` leg to the same fixture and reported `Results: 14 passed, 0 failed`, 27 `[PASS]` / 1 `[SKIP]` / 0 `[FAIL]`, with every memory leg still passing and zero matches for the gate's `FATAL` regex. The base musl gate passes but provides no shared-mmap-specific marker. CPU/SMP stress consumers ran, but the extra stress gate is blocked by its stale gate_log import; workload markers alone are not acceptance. Full race/failure/last-frame-release qualification remains pending. Three runtime cases in `kernel/src/runtime_tests/regression_tests_p0.rs` that sound like §3 coverage are placeholders and verify nothing: `r23_1_cow_tlb_shootdown`, `r174_b4_brk_va_reservation_toctou` and `m0_7_stack_guard_page` return `TestResult::Deferred` on every path. The COW shootdown case is the one to watch: it defers with "requires 2+ CPUs" on one CPU and with "full COW test requires fork + concurrent memory access" on two or more, so a multi-core run changes the deferral message but still checks nothing. COW TLB shootdown and brk VA-reservation TOCTOU are therefore unverified until those bodies are implemented; more CPUs alone does not close them. Stack-guard behaviour is now verified from Ring 3 instead (below), though the `m0_7_stack_guard_page` runtime body itself is still a placeholder. **Guest coverage for the user-stack guard page (added 2026-09-25).** The user stack window is fixed (no stack ASLR), so `test_user_stack_guard` addresses the layout directly rather than provoking it with unbounded recursion. From forked children, since a guard hit is fatal by design: a write at `USABLE_BASE` (`0x7fffffdff000`, the lowest lazy page) must demand-grow and succeed; writes at the top byte (`USABLE_BASE - 1`) and bottom byte (`STACK_BASE`, `0x7fffffdfe000`) of the guard page must each kill the child with exit 139 (`128 + SIGSEGV`). Probing both guard ends catches an off-by-one in the grow bound that would map the top of the guard only. The leg first checks that its own frame lies in `[EAGER_FLOOR, USER_STACK_TOP)`, and fails instead of probing unrelated memory if the layout ever moves. A guard fault prints only `[PF ENTRY]` and takes the `USER_MODE` terminate path, never the `[PAGE FAULT]` kernel branch, so the gate's `FATAL` regex is not tripped. **Guest coverage for fork refusal under `pids.max` (added 2026-09-25).** `test_fork_pids_refusal` attaches to a cgroup with `pids.max = 1` and attempts four forks: each must return `EAGAIN`, the cgroup's `nr_tasks` must be unchanged, and nothing must be reapable. A fork after leaving the cgroup then received pid 7, immediately following the previous leg's pid 6, so the refused forks consumed no PIDs. This pins the observable rollback contract but does not show which refusal point fired — with one task in the cgroup the `check_fork_allowed` pre-check refuses before `attach_task`, so the attach-time rollback in `fork::sys_fork` is exercised only indirectly. See the [lifecycle follow-up](https://github.com/Zero-kernel/Nilix-docs-private/blob/main/design/st-k2-shared-fault-lifecycle-design.md) for the per-AS PT ledger, transient exclusion, shootdown repair, evidence identities and remaining limits.

### 3.3 slab, NUMA, swap, THP

## 4. Process lifecycle, PID1, and waiting (P1)

`sys_wait4` is at `kernel/kernel_core/syscall.rs:7595`; `sys_waitid` at `:23270` is **implemented** (2026-09-25) and dispatched at `:4368` (syscall 247, matching Linux x86_64; already in the seccomp process-management group as `SYS_WAITID` at `kernel/seccomp/types.rs:194`). Both callers share one reap engine, `wait_reap_core` (`:7661`), parameterised by `WaitTarget` (`:7633`) and a `publish` closure that writes the caller's ABI. `process.rs:9525` has namespace-aware orphan reparenting; `try_commit_reaper` is at `:9635`. ROOT-INIT is now registered at boot, and F2's no-current-user-frame fork refusal is implemented (both below).

### waitid

Implemented by extracting the wait4 scan/wakeup path into `wait_reap_core` rather than duplicating it, so both syscalls share selector resolution, namespace filtering, blocking, and rollback. `WaitTarget` covers `P_ALL` (`:23179`, resolved at `:23241`) and `P_PID`; `P_PGID` (`:23183`) returns `EINVAL` fail-closed at `:23248`, on the same grounds `wait4` refuses process groups — process-group membership is not yet a tracked relation, so accepting it would silently behave as `P_ALL` and reap the wrong child. `idtype` and the whole options word are validated before any state change; `WEXITED` is required.

The ABI split is the `publish` closure: `wait4` writes a `c_int` status and returns the namespace PID, while `waitid` writes a 128-byte `siginfo_t` (`si_signo=SIGCHLD`, `si_code=CLD_EXITED`, `si_pid`=namespace PID, `si_uid`, `si_status`) and returns 0. Publication happens **before** the reap commits: a faulting `infop`/`status` pointer restores `Ready`, clears `waiting_child`, leaves the zombie reapable, and returns `EFAULT`, matching Linux. `WNOWAIT` (`:7885`) observes without consuming — the child stays linked and `cleanup_zombie` is not called, so a later wait still reaps it; only the parent's own wait state is undone. `WNOHANG` returns without blocking (0 for `wait4`, a zeroed `siginfo` for `waitid`). `WUNTRACED`/`WCONTINUED` are **rejected with EINVAL** rather than silently ignored, and unknown option bits are rejected too: this kernel records no parent-visible stop/continue event, so accepting them would promise a notification that can never arrive and hang the caller. `wait4` keeps ignoring them only for backward compatibility.

### PID1/reaper and F2

**ROOT-INIT (closed 2026-09-25).** Root PID-namespace init is now registered where every other init is, inside `assign_pid_chain` (`pid_namespace.rs:1499-1513`), instead of through a separate boot hook — the root arm simply stops being skipped when `membership.pid == 1`. `reparent_orphans` STEP 3 (`process.rs:9602`) therefore resolves its fallback reaper from `ROOT_PID_NAMESPACE.init_global_pid()` and falls back to the bare `ROOT_INIT_PID` constant only before pid 1 exists. This matters because the registration is identity-checked and cleared on detach (`clear_init`, `:1229`), so it cannot name a recycled pid, whereas the numeric constant can.

Two asymmetries are deliberate. Root registration is **best-effort** (`let _ = set_init(..)`): unlike the non-root arm, `InitAlreadySet` must not fail chain allocation, because failing the whole PID allocation is a strictly worse regression than keeping an existing mapping. And root is exempt from the init-death cascade (`handle_namespace_init_death` skips `is_root()`, `process.rs:9721`), so registering it starts no kill cascade — verified, not assumed.

Reaper commitment keeps the existing one-lock-at-a-time protocol and generation checks that prevent self-adoption and ABA. pid 1 can never be its own reaper, and an absent/Zombie/Terminated root init takes `reparent_logged_leak` — a deterministic ppid plus a logged leak — rather than a panic, because panicking on the teardown path would re-open the process-abandonment class this slice closes.

**F2 (closed 2026-09-25).** `fork_inner`'s no-frame arm (`fork.rs:660`) used to be reached by any parent whose syscall-frame window was absent, and it seeded the child by copying and rebasing the parent's kernel stack from `parent.context`. That model is sound for a kernel thread and wrong for a Ring-3 parent: it rebuilds exactly the chimera the ST-K3 fix removed one branch above — a kernel `rsp` under user selectors, reaching `ud2` in `switch_to_user`. The arm now refuses a user parent with `ForkError::InvalidUserFrame`, which the syscall layer maps to `EFAULT`.

The discriminator is `kernel_stack_resume_is_admissible(parent.memory_space)` (`fork.rs:520`), i.e. `memory_space == 0` — this kernel's existing kernel-thread test, the same idiom the OOM candidate scan uses. It is deliberately read from the PCB and not inferred from the frame window, because the caller arrives here *precisely because* that window was absent or disowned; a disowned frame therefore cannot forge a user parent into a kernel one. The refusal precedes publication: `fork::sys_fork` (`fork.rs:289-302`, the wrapper that owns child creation) routes every `fork_inner` error through child-link removal, cgroup detach, the scheduler-permit drop and `cleanup_partial_child` (`:300`) before returning, so no child PCB, PID-chain entry, or cgroup charge survives; `syscall.rs`'s `sys_fork` (`:4524`) only maps the resulting `ForkError`. `EFAULT` rather than a transient code is the point — no retry can clear an absent frame, so `ENOMEM`/`EAGAIN` would invite a spin.

Test status is partial and worth stating plainly. Hosted oracles for selector/option validation and `siginfo_t` encoding **executed and passed** on an x86_64 Linux host on 2026-09-25 (§19); they cannot compile on macOS/arm64, so they are remote-only. The two F2 oracles (`f2_frameless_fork_tests`, `fork.rs:470`) cover the predicate only — that a zero `memory_space` admits kernel-stack resume and any non-zero one does not — deliberately, because `fork_inner` itself needs a live address space no hosted fixture provides; the refusal's placement before publication is read from the `sys_fork` error path, not executed. **Guest coverage for `waitid` (added 2026-09-25).** A Ring-3 leg, `test_waitid` in `userspace/src/syscall_test.rs`, now drives syscall 247 through the real dispatch arm against real zombies, and is a named entry in the `ring3_mm_oracle.sh` leg contract, so removing or renaming it fails the gate. ## 5. Threads, TLS, and pthread prerequisites (P1)

Clone flag definitions and rejection are in `syscall.rs:4610-4685`; `CLONE_THREAD/FILES/FS/SIGHAND` combinations are intentionally rejected. Process fields currently include independent rlimits, fd tables, capabilities, and signal state.

Shared signal disposition does not share blocked masks, pending queues, robust lists, or clear-tid. `exit_group` publishes a shared exiting generation before waking siblings. ## 7. IPC, futex, signals, and time (P1)

### Native synchronous IPC and shared memory

Endpoint objects need bounded message slots, sender/receiver queues, close generation, and an admitted payload reservation. Publish only after charge and slot reservation; timeout, peer exit, and namespace teardown wake waiters with a defined errno. `endpoint_call` consumes a reply capability once. Shared memory reuses ST-K2 frame ownership and validates permissions/length/offset at capability invocation.

### Futex and signals

`sys_futex` (`syscall.rs:16349`) currently covers only a subset of Linux operations. Add PRIVATE/SHARED keying, bitsets, requeue, robust-list handling, and bounded PI-chain propagation. Validate user addresses before bucket locks. Add an alternate signal stack, full `siginfo_t`, a bounded real-time queue, and an explicit restart-point table for `SA_RESTART`. Build signal frames only in validated user/alt stacks; copyout failure leaves pending state unchanged. epoll/eventfd/timerfd follow only after the common wait-key/generation contract is stable.

Test timeout/EINTR/restart, PI owner death and requeue, cross-process shared futex, altstack overflow, RT queue limits, endpoint peer exit, SMP races, and copy faults.

## 8. File descriptors and rlimits (P1/P2)

`process.rs:1687-1717` defines 16 rlimit slots; only NOFILE is enforced broadly. Encapsulate the table behind fallible `lookup/reserve/install/replace/close` APIs. A reserve token is invisible until commit and is always canceled on error. Implement `F_GETFD/F_SETFD`, `F_GETFL/F_SETFL`, `F_DUPFD`, and `F_DUPFD_CLOEXEC`; shared open-file-description status makes O_APPEND/O_NONBLOCK visible through dup. Complete get/set/prlimit rules (soft <= hard, privilege to raise hard) and classify every other RLIMIT as enforced or explicitly advisory. Couple fd count with cgroup files.max in one transaction. Test dup/close races, fork/exec CLOEXEC, shared tables, ordinary files on fd 0/1/2, table OOM, NOFILE, and lock-free cleanup.

## 9. VFS, paths, and metadata (P1)

`FileHandle`/`FileLifetime` and the path resolver already support ramfs/ext2/JBD2, cwd/root/pivot, and symlink operations. `sys_statx` (`syscall.rs:17265`) and `sys_chown/fchown/lchown` (`:21797-21808`) are ENOSYS stubs; general dirfd-relative paths and hard links are incomplete.

Resolve relative paths from a cloned, pinned dirfd handle while the PCB lock is held, then release the lock. `PathContext` carries base inode, jail root, mount generation, and final-symlink policy; every step checks execute permission and generation. Absolute paths ignore dirfd; unsupported non-`AT_FDCWD` relative combinations return a documented error.

Add uid/gid/mode/nlink/timestamps/fs-id/mount-id metadata with filesystem transactions. A shared `set_owner` core implements path follow/no-follow and fd variants, `UINT32_MAX` unchanged fields, DAC/CAP_CHOWN, and setid clearing. Hard links are same-filesystem, non-directory, checked-nlink transactions. `statx` uses a `#[repr(C)]` 256-byte structure, mask/flag parsing, and short-buffer copyout. Terminal devices return `ENOTTY` until a real termios state machine exists.

Test dirfd close/non-directory, pivot/umount races, chown permissions, setid, statx masks/short buffers, hard-link/unlink/rename races, cross-mount rejection, and symlink no-follow/loop bounds.

## 10. Storage, durability, and cache (P1; ST-K4)

Use [ST-K4](https://github.com/Zero-kernel/Nilix-docs-private/blob/main/design/st-k4-fsync-writeback-design.md) as the detailed implementation record. Resolve fsync targets from a pinned FileHandle/FileLifetime, release PCB/registry locks before I/O, and choose behavior by object kind rather than numeric fd. Add inode `fsync(datasync)` and filesystem `sync`; Ext2 checks `io_faulted`, retries reachable Busy/NoMem finitely, and returns EIO without converting transient resource exhaustion into permanent poison. The block trait must report actual flush, guaranteed write-through, or unsupported; a missing virtio FLUSH feature cannot silently return success.

Clear dirty bits only after a successful barrier and only through accounted, fs-id-filtered cache APIs. Add dirty-error propagation, error-page refill rules, LRU-detach synchronization, dirty-page pressure handling, and umount sync/invalidation while pinned handles remain alive. `sync_file_range` validates signed values, flags, and overflow and does not claim full Linux durability under write-through.

Extend the guest block profile with slot/generation write-flush-read cycles, checksum records, QMP kill/restart, and fsck/recovery. Validate `valid_slots`, byte counts, checksum, and generation; injected I/O errors must be observable and never reported as successful persistence.

## 11. Networking and netns dataplane (P1/P2)

The stack has virtio-net, IPv4/TCP/UDP, conntrack, and default-DROP policy, but lacks veth, child-namespace RX, routes, per-netns firewall administration, complete loopback, IPv6, wire qualification, and device transfer. RF188-5 is a real defect: the 64-lane fragment hash can collide across live namespaces and cleanup is unbounded.

First key fragments by `(netns_id, fragment_id, src, dst, protocol)`; a lane is only an index hint. Bound per-tick cleanup and drain all namespace fragments during teardown. Then implement veth pairs with pinned namespace/generation and bounded owned RX queues; initialize loopback and route child RX by owner generation. Add longest-prefix routes with interface/gateway checks. Firewall mutations require user-namespace-mapped `CAP_NET_ADMIN`, generation-bound authority, and admitted prepare/commit rules.

Device transfer stays disabled until namespace-FD authority, generation/revocation, child drain, RX/TX quiescence, and rollback are proven. IPv6 follows a separate address/neighbor/ICMPv6/checksum/route design. Physical NIC and external packet observation are deferred; local QEMU only proves the named profile.

Oracles include same-fragment-id isolation, veth bidirectional traffic, route/firewall isolation, loopback, queue-full behavior, namespace teardown, and transfer rollback, with a no-device negative control and independent wire capture when available.

## 12. Namespaces, cgroups, and containers (P1/P2)

## 13. Capabilities, LSM, and seccomp (P1)

Test generation reuse, revocation races, cross-netns admin, LSM rollback, TSYNC with clone/exit, filter OOM, and promise parity.

## 14. Memory/CPU hardening (P1/P3)

`create_kpti_user_pml4` (`kernel/kernel_core/fork.rs:2516`) still copies a coarse 4 GiB entry island. `FULL_KPTI_ISOLATION_SUPPORTED` is intentionally false; early identity mappings have the U55-6 W+X debt; compiler retpoline is unsupported; CPU controls vary by hardware.

Move syscall/interrupt entry, per-CPU scratch, GDT/IDT/TSS, and minimal IST stacks into dedicated linker sections. Build a page-granular trampoline island; user CR3 maps only that island and user pages. Track kernel/user CR3 and PCID generations per process, switch before touching GS/PCB, and handle NMI/IRQ/fault paths in the mapped island. Shared user tables and private roots have separate refcounts and TLB generation checks. Change the support bit only after entry/exit/NMI/switch/fork/exec/teardown probes pass.

Retpoline is enabled only with pinned compiler support and disassembly proof; otherwise compilation continues to reject the feature. The secure matrix tests each missing capability as supported/active/advisory/unsupported. Local QEMU evidence cannot certify full KPTI or physical CPU mitigations.

## 15. VT-d, DMA, and devices (P2/P3; physical work deferred)

QEMU DMAR/Q35/EDU translated DMA, MSI, invalidation, quarantine, and IRTE reuse are covered. Physical endpoint qualification, MSI-X, multiple DRHD/bridge/segment routing, RMRR, scalable mode, ATS/PASID, ACCESS_PLATFORM, and VM-passthrough lifecycle remain open. `kernel/iommu/lib.rs:636` still notes mapping RMRR regions into every affected domain.

Implement RMRR device-scope validation and domain mappings, multi-DRHD/bridge lookup, MSI-X table/PBA ownership with generation-safe teardown, and only then scalable PASID/ATS page-request handling. Negotiate virtio ACCESS_PLATFORM fail-closed. Do not add VM-passthrough code without a real assign/map/unmap/reset/revoke consumer. Physical hardware testing, named matrix rows, hostile DMA, and MSI-X evidence are deferred until hardware is available; QEMU results remain scoped.

## 16. Livepatch (P3; keep disabled for now)

The parser, ECDSA KAT, dependency ordering, and syscall wrappers exist, but production livepatch is unsupported. Keep every mutation path fail-closed with stable ENOSYS/permission behavior until the following are implemented: immutable versioned key manifest; bounded, admitted and read-only image loading; allowlisted symbol/hash matching; stop-machine/RCU quiescence and instruction-cache/TLB synchronization; dependency-ordered disable; and zero active callsites before unload. Inject signature/key/CPU-timeout/page-fault failures and require an all-patches-disabled, hash-clean rollback. No documentation change may flip support.

## 17. Audit, observability, FIPS, and operations (P2/P3)

The audit ring, hash/HMAC, trace/counters, watchdog, profiler, serial kdump, and persistence hook exist, but no production durable/remote backend or performance envelope is qualified. Use a bounded admitted persistence queue and sequence cursor; snapshot outside the ring lock, write from process context, retain unacknowledged cursors, and detect reboot gaps/duplicates. Remote delivery needs authenticated sessions, replay windows, backpressure, and an explicit failure policy. Record key provision/rotation/revoke/use and scrub secret buffers. Counters carry units and overflow bits; performance records include workload, CPU, frequency, temperature, variance, source and image identity. FIPS KAT success is not certification.

## 18. Userspace ABI, dynamic ELF, and compatibility (P2/P3)

The loader is primarily ET_EXEC/static musl; ET_DYN/PT_INTERP/relocations/vDSO are not a complete chain. First gate static ABI layouts (`stat`, `statx`, `siginfo`, `poll`, `rlimit`, clone arguments) with compile-time `repr(C)` oracles. Then implement ET_DYN base selection, checked PT_LOAD permissions, allowlisted RELA relocations, AT_PHDR/AT_BASE/AT_ENTRY, and W^X. Load PT_INTERP as a pinned file object with depth/size bounds and transactional exec rollback. Provide a read-only vDSO with syscall fallback. Only after thread, signal/futex, fd, shared-memory, native capability, VFS, netns, and cgroup contracts pass should glibc/pthread, personality, OCI, and broader applications be enabled. Test ASLR variability, relocation/dependency errors, interpreter absence, vDSO fallback, TLS and robust-futex behavior.

## 20. Handoff checklist

1. Read this slice, the matching roadmap/nextplan row, and any linked deep design; preserve the existing dirty worktree.
2. Re-run `rg` for the cited functions and update line evidence if the premise changed. Record material deviations with date, evidence, and safety impact.
3. Create one per-item design under `docs/review/design/` using the full template for MM/IRQ/ABI/security/lifetime changes; include locks, allocation/Drop, failure matrix, oracle, owner, and independent-review requirement.
4. Implement only a coherent dependency-bounded slice after authorization. Run focused hosted tests before guest/stress gates.
5. Unsupported paths must have stable errno, no side effects, a documented boundary, and a negative test. An implemented dispatch or parser is not evidence of a working capability.
6. Update the nextplan and affected designs. Keep status DRAFT/verification pending when required evidence or independent review is unavailable.

Recommended order: (1) final verification of P0-A/R186-4 and its U23 admission review; (2) final verification of ST-K2-P1, then ST-K4; (3) complete ST-K2-P2 first-touch/teardown semantics, then execute the pending ST-K3-WAITID oracle on x86_64 Linux and close the waitid guest-gate legs (WNOWAIT-then-reap, PID1 exit, reaper race, copyout fault, cgroup/fd rollback), followed by clone sharing and ST-K1/F2/F7 residuals; (4) native capability/IPC, VFS metadata/dirfd, and netns dataplane; (5) six stress profiles and local SMP/security gates; (6) dynamic userspace, OCI, full KPTI, physical VT-d, retpoline, and livepatch only when their external prerequisites exist.
